Nothing opens with DIALOG until you turn it on, for the whole database, for a table or for one form. The settings hold for every process, so set them once at startup, for instance in Fnd\_Hook\_Shell\_Startup. Fnd\_IO\_UseDialog(True)                   turns it on (or off) for every form Fnd\_IO\_UseDialog(->[Table]; True)        for every form of that table Fnd\_IO\_UseDialog(->[Table]; "Input"; True)  for that one form Fnd\_IO\_UseDialog(->[Table]; "Input")     True if that form opens with DIALOG Fnd\_IO\_UseDialog(->[Table])              the same, for the current input form name Fnd\_IO\_UseDialog                         the database-wide setting (False if never set) A form's own setting wins over its table's, and a table's over the database's. Turned on for a table or the database, a form still opens with MODIFY RECORD when Foundation finds that it handles On Validate without calling Fnd\_Hook\_IO\_OnValidate, or cannot tell; turned on for the form itself, it opens with DIALOG regardless.A nil table pointer means a project form. Form names are not case-sensitive.Attributes: Shared, Invisible, Preemptive indifferent| Parameter | Type |  | Description || --- | --- | --- | --- ||first|Variant|➡️|True or False (the database setting), or a table pointer (optional)||second|Variant|➡️|True or False (the table setting), or a form name (optional)||use|Boolean|➡️|True to open the form with DIALOG, False for MODIFY RECORD (optional)||Result|Boolean|⬅️|The value set, or True if the form opens with DIALOG|
