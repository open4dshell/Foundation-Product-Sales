If it can't work out how to format it then it returns the postal code unchanged and sets Fnd.Data.formatError to 1, which Fnd\_Data\_FormatError reports.Anything that is not a letter or a digit is removed first.With no second parameter the country is deduced from the value: five or nine digits is a US ZIP code, and a six character letter-digit-letter-digit-letter-digit value is Canadian.The second parameter has two forms:1. A Longint. Accepted and ignored.2. An object naming the country, which skips the deduction.```Fnd_Data_FormatPostalCode("k1a0b1"; {country: "CA"})  -->  K1A 0B1Fnd_Data_FormatPostalCode("3000"; {country: "AU"})    -->  3000```Object properties, with the default applied when the property is absent:```country  Text  "US", "CA" or "AU". Defaults to deducing it from the value```Attributes: Shared, Invisible, Preemptive indifferent| Parameter | Type |  | Description || --- | --- | --- | --- ||inPostalCode|Text|➡️|The postal code to format||inStyle|Variant|➡️|A legacy style Longint, or an options object (optional)||Result|Text|⬅️|The formatted postal code|
