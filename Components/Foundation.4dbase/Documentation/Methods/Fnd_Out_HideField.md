Wildcards ("@") are honoured, e.g. "@.Password" hides that field on every relation. A column the host's own AddField already defines is unaffected - offer rules never touch a column that's already on the list.Call from wherever the host configures Fnd\_Out for a table (alongside Fnd\_Out\_AddField calls). Mutates the in-memory developer configuration only - it is not written to Resources/Foundation/Fnd\_Out/<Table>.json until a developer explicitly saves a built-in layout or uses the palette's developer-mode "offer" toggle.Attributes: Shared, Invisible, Preemptive indifferent| Parameter | Type |  | Description || --- | --- | --- | --- ||inPath|Text|➡️|A field path, or a wildcard pattern using "@"|
